# 乐启享机器人官网首页重构设计

**Date:** 2026-07-18

**Status:** 已在对话中完成需求确认与方案确认，待写实施计划

**Owner:** Codex session working in `D:\kaifa\.worktrees\steam_fun-20260718-114353-1`

## Goal

把 `steamfun_mirror` 系统的根首页 `/` 重做为 `乐启享机器人` 的对外官网首页，同时保留现有教学系统登录入口与现有老师、学生、管理员业务路由。

最终成果不是简单换皮，而是分两阶段完成：

1. 先在当前系统内做一版高保真 `Orbis.Nft` 风格视觉母版，作为首页重构的视觉骨架。
2. 再把这套骨架替换为 `乐启享机器人` 的正式机构官网首页，接入真实机构内容、真实机构资源和稳定本地引用。

## Confirmed Requirements

以下内容已在对话中明确确认：

1. 本次改造目标是当前系统的根首页 `/`。
2. 现有老师、学生、管理员业务路由与登录后跳转逻辑保持不动。
3. 右上角保留单一 `登录` 入口，点击进入现有统一登录页。
4. 第一阶段先高保真复刻用户提供的 `Orbis.Nft` 提示词效果，不要求一开始就使用机构自有资源。
5. 第二阶段再替换为 `乐启享机器人` 的真实机构内容。
6. 首页主语言全部为中文，英文只作为 logo 附属信息存在，不作为页面主语言。
7. 品牌正式名称为 `乐启享机器人`。
8. 机构定位为 `乐高 / 机器人 / 编程 / AI 科技素养` 综合机构。
9. 正式官网风格不是纯 NFT 暗黑风，而是保留高级感后转为 `蓝橙科技教育风`。
10. 首页优先级是品牌展示优先，不做强销售型首页。
11. 目标受众是 `孩子被吸引，家长做决策`。
12. 招生与经营重点为 `线上线下都有，但线下更重要`。
13. 底部联系方式要并列呈现 `微信 / 电话 / 校区地址`。
14. 首页前半段的主次顺序为：
   - 品牌定位 / 主张
   - 师资团队
   - 学员展示墙
   - 课程入口
15. 完整课程体系页不在首页内重做，首页提供入口后可跳转到现有官网完整课程体系页。
16. 用户要求设计与内容引用必须基于真实参考源，不接受凭空猜测。

## Repo Context

当前仓库不是传统“前端应用 + 后端 API”结构，而是以 FastAPI 为中心的本地镜像与路由重写系统。

已确认的关键上下文：

- 核心入口位于 `src/steamfun_mirror/server.py`
- 根路径与前端捕获页面由 `frontend_asset()` 统一分发
- 当前系统的 `/`、`/login`、`/background/login`、`/school-home-page` 等路径都在同一服务逻辑内
- 现有系统主要服务老师、学生、管理员业务页面，本次官网首页属于在现有业务系统外包裹的一层公共首页

因此，本次首页改造不适合直接修改大量既有捕获页面，而应在服务层为 `/` 增加独立的官网首页响应逻辑。

## Non-Goals

以下内容本次不作为成功标准：

- 只做一个漂亮静态 landing page，但与当前系统无稳定接入关系
- 首页看起来高级，但登录入口、业务路由、现有教学系统被影响
- 大量依赖第三方在线资源，离线或弱网即失效
- 首页只有视觉冲击，没有真实机构内容承接
- 学员墙只是普通相册，没有成长叙事和互动记忆点

## Audience And Product Positioning

首页服务的是 `孩子先被吸引，家长最终决策` 的双层受众。

因此内容与视觉必须同时满足：

- 对孩子：有科技感、未来感、探索感、酷感
- 对家长：有真实师资、有成长结果、有校区空间、有课程路径、有线下可达性

同时由于本次首页以品牌展示优先，不采用传统高压转化型教育页写法：

- 不在首屏堆满预约表单
- 不让销售型 CTA 压过品牌主叙事
- 不做传统教育站式长列表说明书

## Design Direction

正式首页采用 `品牌旗舰型` 路线。

其核心原则为：

1. 先建立品牌记忆点，再建立教育信任感。
2. 保留第一阶段 `Orbis.Nft` 的高完成度视觉骨架。
3. 第二阶段把视觉语义从暗黑 NFT 风转为 `蓝橙科技教育风`。
4. 内容结构采用 `展厅式滚动`，避免做成普通教育网站列表页。

## Homepage Information Architecture

首页整体采用 `前场 4 屏 + 后场 4 屏` 结构。

### 前场 4 屏

前场负责品牌记忆点、视觉冲击与核心可信内容。

#### 1. 首屏品牌宣言

作用：

- 一眼建立品牌气质
- 明确机构定位
- 让用户知道这是科技教育机构，而不是普通兴趣班

固定内容：

- logo
- `乐启享机器人`
- 主标题
- 简短辅助定位
- 单一首页主按钮
- 右上角独立 `登录` 入口

#### 2. 师资团队

作用：

- 快速回应家长的决策逻辑
- 让“高级感”后面立刻接上“真实可信”

不是传统老师列表，而是：

- 创始人主视觉卡
- 团队能力卡组
- 以真实师资海报素材构成高质感团队区

#### 3. 学员展示墙

作用：

- 成为首页最强记忆点之一
- 用真实学员成长证据替代泛泛的“学员风采”

正式表达不叫普通照片墙，而叫：

- `成长穹顶`

内容类型混排：

- 学员图
- 课堂瞬间
- 项目作品
- 获奖现场
- 师生互动

#### 4. 课程入口

作用：

- 用最短内容讲清机构课程结构
- 把用户导向现有完整课程体系页

表现形式：

- 总览说明
- 基础路线 / 高阶路线可视化
- 四个一级课程方向入口
- `查看完整课程体系` 按钮

### 后场 4 屏

后场负责结果证明、空间证明、氛围证明与线下承接。

#### 5. 赛事成果 / 荣誉成果

作用：

- 证明机构不是只有宣传，而是有结果

展示重点：

- 世界机器人大赛
- 代表性领奖现场
- 代表性证书与一等奖成果

#### 6. 校区环境 / 教学场景

作用：

- 承接线下校区决策
- 让家长知道“到店后会看到什么”

展示重点：

- 门店外立面
- 课程体系墙
- 教室空间
- 真实课堂状态

#### 7. 活动视频 / 品牌视频

作用：

- 收束氛围
- 让用户感受到现场而不是只读说明

素材来源：

- `leqixiang_web` 的 showreel 视频

#### 8. 联系方式 / 校区地址 / 咨询入口

作用：

- 为线下到店与咨询提供自然出口

并列呈现：

- 微信咨询
- 电话联系
- 校区地址

不在此处加入强制留资弹窗或压迫式表单。

## Interaction Design

### Navigation

导航采用透明悬浮样式，初始覆盖于首屏之上，滚动后切换为玻璃态半透明导航条。

布局：

- 左：logo + `乐启享机器人`
- 中：少量导航锚点
- 右：单一 `登录` 按钮

中部导航锚点建议为：

- 品牌理念
- 师资团队
- 学员展示
- 课程体系
- 校区与联系

### Login

登录逻辑必须满足：

1. 只提供一个登录入口
2. 不在首页主文案区重复堆放登录按钮
3. 点击后进入现有统一登录页
4. 不改变现有角色识别与跳转机制

### Scroll Rhythm

滚动节奏必须是 `展厅式`，而不是普通内容堆叠式。

前场滚动顺序固定为：

1. 首屏沉浸
2. 师资信任
3. 成长穹顶
4. 课程入口

其核心原因是：

- 如果课程入口过早出现，首页会迅速退化为普通教育站
- 当前任务的目标是品牌旗舰型首页，而不是销售清单页

## Key Section Specifications

### Hero Section

正式首页首屏保留母版的空间感，但内容必须中文化、机构化。

必须包含：

- 品牌 logo
- 品牌名
- 主标题
- 辅助定位
- 单一主按钮

不应包含：

- 传统教育站式多人合影横幅
- 首屏密集留资表单
- 多个相互竞争的 CTA

### Staff Section

师资区采用 `创始人主卡 + 团队能力卡组`。

原因：

- 家长更容易先认识“谁在负责这家机构”
- 然后再理解团队在不同方向上的能力覆盖

内容层次建议：

1. 创始人卡：理念、定位、办学主张
2. 乐高启蒙方向
3. 机器人 / 硬件方向
4. 编程教学方向
5. 教学管理方向
6. 教务服务方向

### Student Dome

学员展示区采用 `成长穹顶`。

交互要求：

- 自动缓慢旋转
- 支持鼠标或触控拖拽
- 支持单卡放大
- 支持前后景深与边缘虚化
- 移动端提供不破坏体验的降级方案

内容排序原则：

1. 课堂状态
2. 项目作品
3. 比赛与领奖
4. 师生互动

设计目标不是“照片越多越好”，而是让用户看到完整成长证据链。

### Course Entry Section

课程区只讲结构，不讲所有细节。

首页内必须呈现：

- `3-16 岁连续成长路径`
- 基础路线
- 高阶路线
- 四个一级方向入口
- 跳转完整课程体系页的按钮

首页内不做：

- 全量课程详情复制
- 冗长课程段落
- 多页式课程说明

### Honors Section

荣誉成果区强调：

- 结果真实
- 过程可验证
- 与课程成长路径相关联

优先使用：

- 世界机器人大赛
- BoxBot
- 乐高挑战赛
- 无人机创意编程
- 代表性一等奖 / 奖牌 / 领奖现场

### Campus Section

空间区不是简单轮播图，而是机构空间叙事：

- 到店第一眼看到什么
- 课程体系如何呈现在空间里
- 教室和课堂状态是什么样

### Video Section

视频区是后场氛围增强模块。

规则：

- 不抢首屏
- 不做整页吵闹自动播放
- 默认主视频窗 + 可切换片段
- 视频加载采用 poster + metadata 优先策略

### Contact Section

底部联系区必须清楚且克制。

并列内容：

- 微信咨询
- 电话联系
- 校区地址

设计要求：

- 便于行动
- 保持品牌气质
- 不要做弹窗轰炸

## Integration Strategy

首页改造的推荐接入方式为：

1. 在 `server.py` 的根路径分发逻辑中，为 `/` 增加独立官网首页响应。
2. 保持 `/login`、`/background/login`、`/school-home-page`、`/code-classroom/*` 等现有系统路径不变。
3. 官网首页与现有 SPA shell 解耦，不通过“修改原捕获首页内容”实现。
4. 官网首页所需资源使用独立命名空间，避免污染既有 `origin/steam.fun` 捕获资源。

## Resource Localization Strategy

### Phase 1

- 允许先使用高保真参考资源
- 但必须本地化到项目目录
- 不允许在页面长期写死第三方远端资源地址

### Phase 2

- 所有视觉核心资源替换为机构自有或可长期稳定持有的资源
- 视频、图片、纹理、图标、师资图、校区图均采用项目内稳定路径

### Asset Stability Rules

必须满足：

1. 资源缺失时有降级占位或静默回退
2. 视频不全量自动预加载
3. 首屏要有 poster 或静态兜底
4. 大图与学员图需要考虑压缩、缩略图与按需加载

## Performance Requirements

正式首页必须兼顾沉浸感与可用性。

最低要求：

1. 首屏在弱网下仍能先看到基本结构与静态内容
2. 视频使用 poster 兜底
3. 学员穹顶支持缩略图优先
4. 移动端不强行保留所有桌面级 3D 开销
5. 不让首页因资源过大而影响登录或后续业务进入

## Mobile Strategy

移动端不是桌面版等比压缩。

移动端要求：

- 导航折叠
- 首屏文案与视觉主体重排
- 成长穹顶提供更轻量但仍有记忆点的体验
- 视频区以点击播放为主
- 联系方式区域更易点击

## Error Handling And Fallbacks

必须考虑以下异常情况：

1. 第一阶段参考视频缺失或解码失败
2. 第二阶段机构视频体积过大
3. 学员墙部分图片缺失
4. 移动端 3D 能力或性能不足
5. 根首页渲染失败时不能影响登录入口与原系统其他路径

处理原则：

- 对首页单独降级
- 不影响现有教学系统可进入性
- 保证至少有纯静态可用首页

## Risks

### Risk 1: 现有仓库不是独立前端站点

风险：

- 首页新增逻辑可能与现有镜像路由逻辑耦合

应对：

- 在服务层单独处理 `/`
- 尽量不侵入现有捕获页面逻辑

### Risk 2: 第一阶段资源版权与替换边界

风险：

- 高保真参考资源与正式长期资源不是同一套

应对：

- 第一阶段资产单独管理
- 第二阶段按命名与目录清晰替换

### Risk 3: 3D 学员墙性能

风险：

- 桌面效果很好，但移动端或低性能设备吃力

应对：

- 提供降级模式
- 图像使用缩略图与按需加载

### Risk 4: 基线测试不干净

当前 worktree 在 2026-07-18 运行 `python -m pytest -q` 的结果为：

- `265 passed`
- `22 failed`

这些失败集中在 `tests/test_server.py` 的本地 fallback、学生作业列表、班级学生关系过滤、dashboard 指标与图表接口等既有逻辑，不是本次首页改造直接引入的故障。

这意味着：

- 后续实现必须把这些失败视为 `前置已知状态`
- 首页任务验收时需要额外证明没有扩大既有故障范围

## Out-Of-Scope Failure Definition

以下情况不算完成：

- 只有视觉稿，没有真实系统接入
- 登录入口失效或跳转错误
- 学员墙退化为普通图墙
- 课程入口与现有课程体系页脱节
- 首页效果只能在一台机器或某个分辨率下看起来正常
- 改动影响原教学系统业务路径
